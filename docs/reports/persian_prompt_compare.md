### 4e. Prompt engineering — vanilla vs improved, full Q&A

For each task, the *same tricky question* is asked twice on a strong model (Gemma-4-31B) and an error-prone model (Mistral-7B): first with the raw dataset prompt (**vanilla**), then with an improved Persian prompt built from the 4-component framework. Answers are shown in full (untruncated) with RTL layout. `✅/❌` = model hit the gold answer.

#### The prompt-engineering format (4-component framework)

Every improved prompt wraps the **same question** with a short Persian instruction built from four components. Together they pin down *who the model is*, *what the task is*, *what it must not do*, and *the exact output shape* the scorer accepts:

| Component | Purpose | Persian example |
|---|---|---|
| **ROLE** | who the model is (task identity) | `شما یک متخصص ریاضی هستید` (you are a math expert) |
| **CONTEXT** | what the task is / what is given | `مسئله را قدم‌به‌قدم حل می‌کنید` (you solve step-by-step) |
| **CONSTRAINTS** | what NOT to do (no prose, no explanation, one answer) | `بعد از پاسخ نهایی هیچ عدد دیگری ننویسید` (nothing after the final answer) |
| **OUTPUT FORMAT** | the exact shape the scorer expects | `[پاسخ نهایی] عدد` (final-answer block) |

The 7 templates (one per task, 35–52 Persian words each) are defined in `IMPROVED_TEMPLATES` in `scripts/eval_persian.py`. The same question is then fed to the model either **bare** (vanilla) or **prefixed with the template** (improved):

```text
improved_prompt(task, question) = IMPROVED_TEMPLATES[task] + "\n" + question
```
