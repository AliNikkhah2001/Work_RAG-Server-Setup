1. FINDINGS (why dana-rag-prod Build images failed)
-------------------------------------------------------------------------------

Builds #21 / #22 failed at "Build images" with:

    docker: command not found

Later builds (through #25) evolved to:

    unknown shorthand flag: 'f' in -f

while HealthCheck Pages still showed stack HEALTHY (apps/QA up). Evidence:
  /var/lib/dana-health/Work_RAG_HealthCheck/logs/*/meta/jenkins/
  (console_excerpt, compose-build.log, diagnosis.json, ci-evidence/)

Root cause (two layers):
  A. Historical: docker-compose.h200.yml bind-mounted HOST /usr/bin/docker.
     Host CLIs are dynamically linked. Inside the container the ELF interpreter
     (ld-linux) is missing → kernel ENOENT → bash prints "command not found"
     (looks like PATH, but it is not). Image also lacked static /usr/local/bin/docker.
  B. Why "yesterday's merges didn't apply" on this machine:
     - Umbrella origin/main ALREADY had PRs #95/#98/#99/#100 (HEAD 0663e2a).
     - git pull alone does NOT recreate the Jenkins controller.
     - dana-jenkins-prod was last started with ONLY:
         docker-compose.yml + docker-compose.gpu.yml
       MISSING docker-compose.h200.yml → sock-only / static-CLI overlay never applied.
     - Image tag dana-jenkins:production still pointed at the old digest without CLI.
  C. Partial CI self-heal made things look different but still broken:
     - ci_resolve_docker.sh fetched static docker into .ci-bin/docker
     - WITHOUT compose plugin → `docker compose -f …` → unknown shorthand flag: 'f'
  D. diagnosis.json often labeled webui_image_skipped_no_npm_build — secondary.
     Real gate was compose build failing instantly.

Iran mirrors / dash `source` issues were separate and already fixed earlier (#95/#92/#93).

Do NOT re-add the host /usr/bin/docker bind-mount.
Do NOT switch the controller to bare jenkins/jenkins:lts (drops Multibranch jobs).
Do NOT run `pkill python` on this host.
Do NOT recreate Jenkins with only yml+gpu on H200 (omitting h200.yml).
